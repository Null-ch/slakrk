# План разработки «Моё похудение»

## Архитектура

Однопользовательское русскоязычное приложение React + TypeScript со сборкой Vite, Tailwind для мобильного интерфейса, React Router для страниц и Lucide для иконок. Nginx в Docker раздаёт статическую сборку и поддерживает прямые ссылки. После установки PWA тот же клиент работает офлайн, персональные записи остаются на устройстве.

- `src/pages` и `src/components` отвечают за экраны и отображение состояния.
- `src/data` хранит начальные значения, шаблоны меню и тренировок.
- `src/domain` содержит функции расчёта, календарные правила и типы. Локальные даты хранятся как YYYY-MM-DD, время создания записи хранится отдельно.
- `src/db` содержит версионируемую схему Dexie, миграции и репозитории. Основные сущности — профиль, настройки, программа, дни, продукты, рецепты, шаблоны меню, дневник еды, тренировки, ходьба, вес и списки покупок.
- Zod проверяет пользовательский ввод и версию резервной копии. Recharts строит графики из дневников. История питания и тренировок хранит снимки параметров на момент записи.

## Этапы и критерии приёмки

1. **Основа.** Vite, строгий TypeScript, Tailwind, мобильная главная, нижняя навигация по реализованным экранам и Docker. Проверка типов и сборки, запуск контейнера и переход по прямой ссылке.
2. **Профиль и вес.** Dexie с транзакционной инициализацией, редактирование параметров и целей, настройки темы, добавление, изменение и удаление веса и талии, среднее за семь календарных дней. Проверка сохранения после перезапуска и корректного расчёта на пустом журнале.
3. **Питание.** Каталог с источниками и состоянием продуктов, редактор порций и рецептов с выходом готового блюда, четыре группы приёмов пищи, копирование и недавние продукты. Перенос недельного меню с исходными граммовками, расчёт калорий и БЖУ по ингредиентам, вывод разницы с целями и поддержка замен. Проверка арифметики, копирования и сохранения истории после обновления справочника.
4. **Тренировки и ходьба.** Программы А и Б, разминка и отдых, техника и иллюстрации, ввод фактических подходов и повторений, замены упражнений, история и дневник дорожки. Проверка восстановления незавершённой тренировки, недельных агрегатов и записи самочувствия.
5. **Программа и прогресс.** Старт программы, 21 день с ручным закрытием или пропуском, чек-листы, покупки по неделям с ручными позициями и графики из реальных записей. Подключение сводок к главной. Проверка дней отдыха, пропусков, перехода между неделями и отсутствия дублирования покупок.
6. **Офлайн и перенос данных.** vite-plugin-pwa, манифест и иконки, версионируемый JSON с предварительной валидацией и транзакционным восстановлением после подтверждения, три CSV, локальные напоминания и календарный экспорт. Проверка установки на Android через HTTPS, работы в авиарежиме, обновления PWA и переноса резервной копии между браузерами.

После каждого этапа — проверка типов, production-сборка и проверка реализованных сценариев.

## Неопределённости ТЗ

- По формуле Миффлина — Сан Жеора исходные параметры дают 2026,25 ккал основного обмена и 2431,5 ккал при коэффициенте 1,2. Значения 1991 и 2390 из ТЗ с ними расходятся. Цели 1950 ккал и 150/65/190 г остаются исходными, энергетическая оценка по БЖУ составляет 1945 ккал.
- У ряда ингредиентов отсутствует масса, указан только счёт в штуках либо не указаны вид, жирность или состав. Для точной суммы нужны масса съедобной части, маркировка либо документированное редактируемое допущение. Дни с неуточнённым составом должны показывать неполный итог, сохраняя блюда и заданные массы.
- Дата старта и пропущенные дни требуют двух отдельных значений. Календарная дата показывает, сколько дней прошло, а активным остаётся первый незакрытый день. Пользователь может завершить его или отметить пропущенным.
- Меню задано по дням недели, старт программы может быть в любой день. Базовое правило для реализации — привязывать блюда к локальному дню недели и показывать фактические даты в календаре.
- Для недельных показателей ходьбы предлагается календарная неделя с понедельника. Для сводки программы используются её собственные недели. На днях отдыха тренировка и ходьба исключаются из обязательных задач.
- Возможность PWA работать в фоне зависит от браузера. Первичная реализация выдаёт напоминания внутри открытого приложения и экспортирует события в календарь. Очистка данных браузера удаляет IndexedDB, поэтому нужен проверяемый экспорт.
- HTTPS потребуется для проверки установки PWA на телефоне. Локальный HTTP используется для проверки первого этапа.
